# 文件占用模块验证报告

2026-10-09，Windows 11 x64 实机。交付版本为 HardwareScope 1.1.0 与 FileGuard 1.0.0。测试仅创建临时文件、目录和一次性子进程，没有结束用户现有应用或更改用户文件内容。

## 文件操作与权限

安装后的普通用户服务测试通过 31 项，管理员测试通过 35 项；普通用户测试中仅跳过需要管理员创建高权限测试进程的分支，管理员测试覆盖该分支。实际文件锁阻止重命名和删除；只释放勾选的句柄后，测试进程继续运行，文件内容和另一个文件锁仍保留，已释放文件可以重命名和删除。结束所选测试进程后，其余文件和内存映射释放。

已验证中文及空格路径、文件夹子目录占用、相邻目录前缀排除、无占用文件、映射占用、过期进程创建时间、过期句柄校验值、请求路径范围及关键系统 PID 拒绝。服务通过独立进程处理查询；不同请求的句柄身份校验值保持稳定，返回的是带密钥的 HMAC 校验值，没有返回原始内核地址。

管理员测试使用自己创建的高权限测试子进程和同账号的受限中等完整性令牌，确认普通权限客户端不能查看或结束该高权限子进程，操作明确返回拒绝访问。实际服务管道收到格式错误的请求时也返回拒绝；源码审查确认本地管道权限不允许普通用户创建同名服务端，并核对客户端连接的服务进程身份。

普通权限免安装测试通过发现占用、拒绝无法核验身份的句柄释放、拒绝过期实例和精确结束测试进程。Windows 在普通权限下隐藏内核对象身份，因此成功的强制句柄释放由已安装服务测试覆盖。

## 服务与安装

安装生命周期脚本的 19 项检查全部通过，覆盖手动启动与延迟自动启动设置、停止和启动、卸载时移除服务/文件右键项/文件夹右键项/应用路径注册、重新安装以及安装文件与构建文件的 SHA-256 一致性。普通用户尝试以写入方式打开安装后的服务程序被拒绝；文件所有者为 Administrators。

服务实测位于会话 0，主窗口句柄为 0。12.01 秒空闲观察中 CPU 时间增量为 0 毫秒，工作集 10,326,016 字节（约 9.85 MiB），私有内存 1,626,112 字节（约 1.55 MiB）。这是本机短期观察，不能保证其他电脑的内存数值完全相同；服务代码没有定时采样、文件轮询、联网或持续日志写入。

独立原生程序为 259,072 字节，独立安装程序约 2.1 MiB，不需要 .NET 或单独安装 C++ 运行库。HardwareScope 文件占用页面已通过隔离配置启动、原生 WPF 渲染和截图检查；独立窗口的路径、占用表、服务状态和按钮显示已通过只读截图检查。

## 验证边界

管理员扫描会跳过禁止操作的系统进程句柄，避免系统设备句柄阻塞查询；文件查询可由 Windows Restart Manager 补充可识别的受保护占用，目录查询可能无法列出这类占用。受保护进程、内核驱动和所有网络文件类型没有完整覆盖。普通用户不能借助服务绕过其他用户或高权限进程的权限。

强制释放句柄仍可能使目标应用出错、崩溃或丢失未保存数据；Windows 没有原子化的跨进程句柄比较并关闭接口，不能消除所有句柄复用竞争。真实设备重启没有执行，已验证服务配置为延迟自动启动、SCM 启动与停止，以及会话 0 的静默运行。

原始记录位于 `artifacts/verification/1.1.0`：`fileguard-native.json`、`fileguard-service.json`、`fileguard-service-elevated.json`、`fileguard-install-lifecycle.json`、`fileguard-service-idle.json`、`binary-write-protection.json`，以及集成页面截图。验证 ZIP 只包含结果和截图，不含监控配置或连接凭据。
