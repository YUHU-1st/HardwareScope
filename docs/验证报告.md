# HardwareScope 1.0.1 验证报告

验证日期：2026-10-09（北京时间）。本次针对缺失读数和总览温度显示修复；结果来自当前电脑，不推断所有设备都开放传感器。

## 本次修复

Windows 总览保留负载卡和趋势，在前部增加逐设备的「全部硬件温度」区，覆盖主板、CPU、GPU、NPU、内存、显存、每块存储和每张网卡。多个温度源保留名称，可展开并跳转到对应曲线；不可读项有具体原因和来源提示。安卓 1.0.1 同步增加八类设备温度及对应详情、曲线。

旧版标准权限没有取得磁盘温度，新版采用 Windows 只读 NVMe SMART 查询，现已在标准权限下恢复两块 SSD 各三个真实温度，十秒刷新并标明上次时间。旧版关闭了 DIMM 采集，新版按实际 PawnIO 访问权限启用 CPU 和 DIMM SPD 通道，管理员模式已恢复两条内存温度。没有安装新驱动，也没有修改超频设置、驱动保护或系统安全设置。

SSD 的 Warning / Critical Temperature 与 DIMM 的温度上下限、测温分辨率是参数，现归为其他指标，不再冒充当前温度。管理员模式还发现并修复了 ETW 初始化顺序错误：在启用内核提供程序前打开事件源会使整轮监控停止；修复后温度及进程网络速率均正常返回。[TraceEvent 官方源码](https://github.com/microsoft/perfview/blob/main/src/TraceEvent/TraceEventSession.cs)

## 当前电脑实测

Lenovo 83RU / LNVNB161216，AMD Ryzen 9 9955HX3D，32 GB 内存，NVIDIA GeForce RTX 5080 Laptop GPU，Windows 11。以下是测试快照，温度随工作负载变化。

| 分类 | 标准权限 | 管理员权限 |
|---|---|---|
| CPU | Windows 占用率及系统报告频率；底层温度因 PawnIO 访问被拒绝，明确提示管理员入口 | Tctl/Tdie 73.25°C，CCD1 47.375°C、CCD2 67°C，另有 CCD 最高/平均；核心时钟、CPU 封装及分核心功耗可读 |
| GPU | NVML 核心温度 44°C，并读取频率、负载、功耗、驱动限制状态 | 同一驱动接口可读 |
| 显存 | GPU Memory Junction 52°C，有容量、使用量及频率 | 同一驱动接口可读 |
| 梵想 S910MAX 4TB | 综合 39.85°C、两个独立温度传感器 56.85 / 39.85°C，对应 PHYSICALDRIVE1 | 综合 39.85°C、独立传感器 59.85 / 39.85°C；报警阈值不计为当前温度 |
| 三星 MZVLC1T0HFLU-00BL2 | 综合 47.85°C、两个独立传感器 72.85 / 47.85°C，对应 PHYSICALDRIVE0 | 综合 48.85°C、独立传感器 74.85 / 48.85°C；报警阈值不计为当前温度 |
| 两条 Samsung DDR5 内存 | 容量、使用量、固件配置传输率；SPD 测温因驱动访问权限不可读 | DIMM #0 47°C、DIMM #1 43.75°C；分辨率及上下限另列 |
| 主板 | 底层设备权限不足，明确原因 | 驱动可访问，但本机主板 / 厂商 EC 未提供受支持的温度、风扇接口 |
| NPU | 本机未检测到公开 NPU 设备 | 同左，不以 GPU AI 负载替代 |
| 网卡 | 流量、链路状态和速率可读；驱动没有公开温度 | 权限不能补足未公开的传感器；虚拟接口也没有独立物理芯片温度 |
| 分进程网络 | 明确要求管理员权限 | ETW 正常返回，快照中 569 个进程有网络速率字段，其中 17 个有非零流量 |

NVMe 温度由整数 Kelvin 转换为摄氏度，不与阈值混用。GPU 补充温度、NVMe SMART 和 DIMM SPD 每十秒更新；CPU 占用率与支持的底层 CPU 指标按当前采样间隔更新，默认两秒。DIMM 首次发现需要访问 SMBus，本机管理员硬件初始化约 4.2 秒。

管理员快照共有六个设备提供温度：CPU、GPU、物理内存、显存、两块 SSD。无法读取的设备仍保留温度位置及真实原因；管理员权限不是对全部厂商传感器的保证。

## 已执行检查

- Windows Release 构建零警告、零错误；自包含 Windows x64 发布成功。
- 标准权限与管理员权限各 28 项 Core / HTTPS / 进程控制检查全部通过，包括真实快照、缺失原因、证书固定、错误密钥、撤销授权、设置备份、优先级、安全结束一次性测试进程和干净退出。
- 最终自包含程序的普通权限与管理员总览、存储温度区域均加载真实读数、生成截图并正常退出；已检查布局、多个温度和长设备名称。其余原有页面保持原功能。
- Android 1.0.1 使用原 RSA-3072 发布密钥签名，APK v2 验证通过；677376 字节，SHA-256 为 `13c870874adf8165087ffb1bc758f0059362bbbd850b89e3984a7aaf3e6c6f44`。13 项测试通过，含五项温度回归；lint 零错误，保留五项既有国际化提示。此次没有提供私有 PC 集成文件，两个可选的 JVM-PC 集成测试跳过；这些传输测试在 1.0.0 已执行过，不能表述为本次安卓实机验证。

独立硬件诊断（不含 WPF、进程表和网络 ETW）的整机 CPU 开销约 0.207%（标准权限）和 0.236%（管理员），工作集约 101 / 143 MiB。这个短时诊断不能替代完整应用长期基准；界面仍显示实际监控 CPU、内存及采样耗时。1.0.0 的一分钟托盘平均 CPU 0.109% 是旧版结果，不能直接当作 1.0.1 实测值。

安装包及最终压缩文件的验证记录与 SHA-256 清单随交付提供。旧版 1.0.0 发布文件仍保留在上一层目录，本次更新文件均在 `artifacts/release/1.0.1`。

本机没有连接安卓手机或现成模拟器，安卓真机布局、Keystore、实际蓝牙配对、vivo 后台策略与跨网连接仍未实测。主板 EC、其它品牌 GPU、其它主板和 NPU 的传感器需要对应设备验证；没有以其他部件温度补齐缺失值。超频写入软件没有统一审计来源，仍明确无法可靠归因。
